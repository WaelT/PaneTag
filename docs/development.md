# Development

## Layout

```
PaneTag/
├── src/
│   └── PaneTag.cs        the helper: pseudo console, output/input rewriting, bar drawing, pipe server
├── PaneTag/              the PowerShell module (this folder is what gets installed)
│   ├── PaneTag.psd1      module manifest (version, exports)
│   ├── PaneTag.psm1      Set-PaneTag / ptag
│   └── panetag.exe      build output (generated by build.ps1)
├── tests/
│   ├── PtyHarness.cs       hosts a command in a headless pseudo console and prints its output
│   └── smoke.ps1           builds everything and runs the smoke tests
├── docs/                   this documentation
├── build.ps1               compiles src/PaneTag.cs
└── install.ps1             builds and installs the module
```

## Building

```powershell
.\build.ps1
```

This compiles `src\PaneTag.cs` into `PaneTag\panetag.exe` with
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, the compiler that ships with
.NET Framework. No SDK, NuGet or project file is involved.

### Language limits

That compiler only supports **C# 5**. These newer features don't compile:

| Not available | Use instead |
| --- | --- |
| `$"interpolated {strings}"` | `"text " + value` or `string.Format` |
| `a?.b`, `nameof(x)` | explicit null checks, string literals |
| `int M() => 1;` | normal method bodies |
| `out var x` | declare the variable first |
| `using static`, tuples, pattern matching, `default` literals | older equivalents |

It targets .NET Framework 4.x, so only APIs from that framework (plus `System.Core.dll`) are available.

### The `\x` escape trap

In C#, `\x` takes **one to four** hex digits. `"\x1b7"` is the single character U+01B7, not
ESC followed by `7`. Use `\u001b` when the next character is a hex digit (0-9, a-f, A-F).
The code defines `SaveCursor` and `RestoreCursor` constants for the two sequences where
this matters.

## Testing

### Smoke tests

```powershell
.\tests\smoke.ps1            # build, then test
.\tests\smoke.ps1 -NoBuild   # test the existing build
```

The script compiles `tests\PtyHarness.cs` into `%TEMP%\panetag-tests`, runs scenarios
in a headless 60×10 pseudo console, and checks the output. The output is what the
pseudo console renders, with ESC shown as `\e`, BEL as `\a` and CR as `\r`.

| Scenario | Checks |
| --- | --- |
| Alternate screen | The bar is drawn; the app sees 9 rows; text the app puts on its row 1 lands on row 2; the bar is redrawn after entering the alternate screen, clearing it and leaving it; the exit code (7) passes through. |
| Pipe rename | The harness renames the bar over the pipe and the new title appears. |
| Module | `Set-PaneTag -Command` starts a bar; `Set-PaneTag` inside renames it; the exit code (3) reaches the outer shell. |
| `--rename` | From cmd and from Git Bash inside a pane, `panetag --rename` works by bare name (checks the PATH change), joins unquoted words and applies `-c`. The Git Bash check is skipped if Git isn't installed. Outside a pane it exits 1 with a clear message. |

The harness re-renders through a second pseudo console, so its output shows the resulting
screen updates rather than the exact bytes `panetag.exe` wrote. For example, margins
don't appear in it. Use it to check where things end up on screen.

To capture output for your own scenario:

```powershell
$harness = "$env:TEMP\panetag-tests\PtyHarness.exe"   # built by smoke.ps1
& $harness 80 24 10000 "$PWD\PaneTag\panetag.exe -t Debug -- cmd /c dir"   # from the repo root
```

Arguments: columns, rows, timeout in ms, command line, and optionally a title to send over
the pipe after 1.5 s (that only works when the command is `panetag.exe` itself, since
the pipe name uses the direct child's process ID).

When writing command lines in Windows PowerShell 5.1, pass nested commands as base64
(`--cmd-b64`, `-EncodedCommand`) like `smoke.ps1` does. Embedded double quotes are
mangled otherwise.

### Manual checks in Windows Terminal

The smoke tests can't check how things actually look, or how scrollback behaves. Before
releasing a change, check these in a real Windows Terminal pane, with both a top and a
bottom bar:

- [ ] `ptag Test`, then run `dir` several times until it scrolls: the bar stays in place.
- [ ] Bottom bar: earlier output is reachable in scrollback.
- [ ] `claude`: the bar stays through a long reply, the app title shows on the right, the
      tab title reads `Test · …`.
- [ ] `codex`: the same.
- [ ] A full-screen app (`edit`): the bar stays; quitting returns to the shell with the bar intact.
- [ ] Resize the window and split/close neighboring panes: the bar is redrawn and the app reflows.
- [ ] `cls` / `Clear-Host`: the bar comes back.
- [ ] `ptag Renamed` and `ptag -Color red` inside the pane.
- [ ] Ctrl+C interrupts the app, not the bar. Pasting multi-line text works.
- [ ] `exit`: the bar row is cleared, the original tab title returns, the shell works normally.

## Making changes

- **New escape sequence handling:** add it in `OnCsi`, `OnEsc`, `OnEscInter` or `OnOsc`.
  Rewrite only what refers to absolute rows or can wipe the bar row. Everything else
  should pass through unchanged. Add a row to the table in
  [architecture.md](architecture.md#output-rewriting).
- **Terminal state:** read and write it only while holding `gate`. Draw the bar only via
  `TryFlushHeader`, which checks that it's safe.
- **New pipe command:** add a `case` in `ApplyCommand`, a parameter in `Set-PaneTag`,
  and document it in [usage.md](usage.md) and [architecture.md](architecture.md#rename-pipe).
- **New `panetag.exe` option:** parse it in `Program.Main`, add it to the `Usage` text
  and to [usage.md](usage.md).
- **Module code** must stay compatible with Windows PowerShell 5.1: no ternary operator,
  `??`, `?.` or `&&`/`||` pipeline chains.

## Releasing

1. Update `ModuleVersion` in `PaneTag\PaneTag.psd1`.
2. Add an entry to [CHANGELOG.md](../CHANGELOG.md).
3. Run `.\tests\smoke.ps1` and the manual checks.
4. Run `.\install.ps1` to update your installed copy.
