# Development

## Layout

```
PaneTag/
├── src/
│   └── PaneTag.cs          the helper: pseudo console, output/input rewriting, bar drawing, pipe server
├── PaneTag/                the PowerShell module (this folder is what gets installed/published)
│   ├── PaneTag.psd1        module manifest (version, exports, Gallery metadata)
│   ├── PaneTag.psm1        Set-PaneTag / ptag, Enable-/Disable-PaneTagClaudeHooks
│   ├── panetag.exe         build output (generated by build.ps1, not committed)
│   └── ptag.exe            copy of panetag.exe, so `ptag` works in any shell inside a titled pane
├── tests/
│   ├── PtyHarness.cs       hosts a command in a headless pseudo console and prints its output
│   └── smoke.ps1           builds everything and runs the smoke tests
├── tools/
│   ├── publish.ps1         builds, tests and publishes to the PowerShell Gallery
│   └── demo/               play.ps1 + scene.ps1: the README demo, for recording by hand
├── docs/                   this documentation; assets/panetag-demo.gif is the README demo
├── .github/workflows/      smoke.yml runs the smoke tests on every push
├── build.ps1               compiles src/PaneTag.cs
└── install.ps1             builds and installs the module from source
```

## Building

```powershell
.\build.ps1
```

This compiles `src\PaneTag.cs` into `PaneTag\panetag.exe` with
`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, the compiler that ships with
.NET Framework. No SDK, NuGet or project file is involved.

### Language limits

That compiler only supports **C# 5**. These newer features don't compile:

| Not available | Use instead |
| --- | --- |
| `$"interpolated {strings}"` | `"text " + value` or `string.Format` |
| `a?.b`, `nameof(x)` | explicit null checks, string literals |
| `int M() => 1;` | normal method bodies |
| `out var x` | declare the variable first |
| `using static`, tuples, pattern matching, `default` literals | older equivalents |

It targets .NET Framework 4.x, so only APIs from that framework (plus `System.Core.dll`) are available.

### The `\x` escape trap

In C#, `\x` takes **one to four** hex digits. `"\x1b7"` is the single character U+01B7, not
ESC followed by `7`. Use `\u001b` when the next character is a hex digit (0-9, a-f, A-F).
The code defines `SaveCursor` and `RestoreCursor` constants for the two sequences where
this matters.

## Testing

### Smoke tests

```powershell
.\tests\smoke.ps1            # build, then test
.\tests\smoke.ps1 -NoBuild   # test the existing build
```

The script compiles `tests\PtyHarness.cs` into `%TEMP%\panetag-tests`, runs scenarios
in a headless 60×10 pseudo console, and checks the output. The output is what the
pseudo console renders, with ESC shown as `\e`, BEL as `\a` and CR as `\r`.

| Scenario | Checks |
| --- | --- |
| Alternate screen | The bar is drawn; the app sees 9 rows; text the app puts on its row 1 lands on row 2; the bar is redrawn after entering the alternate screen, clearing it and leaving it; the exit code (7) passes through. |
| Pipe rename | Plain words start a bar with that title; the harness renames the bar over the pipe and the new title appears. |
| Module | `Set-PaneTag -Command` starts a bar; `Set-PaneTag` inside renames it; the exit code (3) reaches the outer shell. |
| `ptag` inside a pane | From cmd and from Git Bash inside a pane, `ptag New title` works by bare name (checks the PATH change and the `ptag.exe` copy), joins unquoted words and applies `-c`. The Git Bash check is skipped if Git isn't installed. Starting a second bar with `ptag X -- cmd` is refused. |
| Status | `ptag --status` shows the label in orange; a keypress typed by the harness clears it; `--sticky` survives the keypress until `--clear-status`; outside a pane it's a silent no-op. |
| Claude hooks | `Enable-PaneTagClaudeHooks` on a temp settings file keeps existing settings and hooks, doesn't duplicate on a second run, backs up under unique names; `Disable-PaneTagClaudeHooks` removes only PaneTag's entries. |

The harness can type into the pane: a sixth argument is sent as keystrokes after 3 s
(pass `-` as the fifth argument to skip the rename).

### End-to-end check with Claude Code

This runs the real Claude Code with PaneTag's hooks from a temporary settings file (your
own settings are untouched) and sends one tiny prompt on your account:

```powershell
$work = "$env:TEMP\panetag-tests"
Import-Module .\PaneTag\PaneTag.psd1 -Force
Enable-PaneTagClaudeHooks -SettingsPath "$work\e2e-settings.json"
$child = "cmd /c `"claude -p `"Reply with just ok`" --settings $work\e2e-settings.json & ping -n 4 127.0.0.1 >nul`""
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($child))
& "$work\PtyHarness.exe" 80 12 90000 "$PWD\PaneTag\panetag.exe -t E2E --cmd-b64 $b64" | Select-String 'Your turn'
```

A match means Claude's `Stop` hook flagged the bar.

The harness re-renders through a second pseudo console, so its output shows the resulting
screen updates rather than the exact bytes `panetag.exe` wrote. For example, margins
don't appear in it. Use it to check where things end up on screen.

To capture output for your own scenario:

```powershell
$harness = "$env:TEMP\panetag-tests\PtyHarness.exe"   # built by smoke.ps1
& $harness 80 24 10000 "$PWD\PaneTag\panetag.exe -t Debug -- cmd /c dir"   # from the repo root
```

Arguments: columns, rows, timeout in ms, command line, then optionally a title to send over
the pipe after 1.5 s (`-` for none; it only works when the command is `panetag.exe` itself,
since the pipe name uses the direct child's process ID) and keys to type after 3 s.

If you run tests from inside a titled pane (Claude Code often is), `PANETAG_PIPE` is set
and `panetag.exe` updates that pane's bar instead of starting a test bar. `smoke.ps1`
clears it at the start; clear it yourself (`$env:PANETAG_PIPE = $null`) for ad-hoc runs.

When writing command lines in Windows PowerShell 5.1, pass nested commands as base64
(`--cmd-b64`, `-EncodedCommand`) like `smoke.ps1` does. Embedded double quotes are
mangled otherwise.

### Manual checks in Windows Terminal

The smoke tests can't check how things actually look, or how scrollback behaves. Before
releasing a change, check these in a real Windows Terminal pane, with both a top and a
bottom bar:

- [ ] `ptag Test`, then run `dir` several times until it scrolls: the bar stays in place.
- [ ] Bottom bar: earlier output is reachable in scrollback.
- [ ] `claude`: the bar stays through a long reply, the app title shows on the right, the
      tab title reads `Test · …`.
- [ ] `codex`: the same.
- [ ] A full-screen app (`edit`): the bar stays; quitting returns to the shell with the bar intact.
- [ ] Resize the window and split/close neighboring panes: the bar is redrawn and the app reflows.
- [ ] `cls` / `Clear-Host`: the bar comes back.
- [ ] `ptag Renamed` and `ptag -Color red` inside the pane; `! ptag Renamed` inside Claude Code.
- [ ] With `Enable-PaneTagClaudeHooks`: the bar turns orange when Claude finishes and red at a
      permission prompt (a few seconds after it appears), and clears when you type.
- [ ] Ctrl+C interrupts the app, not the bar. Pasting multi-line text works.
- [ ] `exit`: the bar row is cleared, the original tab title returns, the shell works normally.

## Making changes

- **New escape sequence handling:** add it in `OnCsi`, `OnEsc`, `OnEscInter` or `OnOsc`.
  Rewrite only what refers to absolute rows or can wipe the bar row. Everything else
  should pass through unchanged. Add a row to the table in
  [architecture.md](architecture.md#output-rewriting).
- **Terminal state:** read and write it only while holding `gate`. Draw the bar only via
  `TryFlushHeader`, which checks that it's safe.
- **New pipe command:** add a `case` in `ApplyCommand`, a parameter in `Set-PaneTag`,
  and document it in [usage.md](usage.md) and [architecture.md](architecture.md#rename-pipe).
- **New `panetag.exe` option:** parse it in `Program.Main`, add it to the `Usage` text
  and to [usage.md](usage.md).
- **Module code** must stay compatible with Windows PowerShell 5.1: no ternary operator,
  `??`, `?.` or `&&`/`||` pipeline chains.

## Recording the demo GIF

`tools\demo\play.ps1` plays the README demo in a full-screen, 4-pane Windows Terminal
window; `tools\demo\scene.ps1` is what each pane runs. Two panes run real Claude Code
sessions (two small prompts) with a temporary settings file that only holds PaneTag's hooks.

1. Run `.\tools\demo\play.ps1` and start your screen recorder during the countdown.
2. Don't touch the demo window. It closes by itself after `-Seconds` (default 45): the scenes
   exit on a stop file and the demo's Claude sessions are ended, so every pane exits normally.
3. Convert the recording, for example:
   ```powershell
   ffmpeg -i demo.mp4 -an -filter_complex "fps=10,scale=1720:-1:flags=lanczos,split[a][b];[a]palettegen=max_colors=128:stats_mode=diff[p];[b][p]paletteuse=dither=none:diff_mode=rectangle" docs\assets\panetag-demo.gif
   ```

Don't automate the capture or close the window from outside: Windows won't bring a window
to the front for a background script (so a screen-area capture can record whatever is on
top), capturing the window by title gives black frames because Windows Terminal draws with
the GPU, and closing a Windows Terminal window from another process crashed Windows
Terminal, taking every open tab with it.

## Releasing

1. Update `ModuleVersion` in `PaneTag\PaneTag.psd1`.
2. Add an entry to [CHANGELOG.md](../CHANGELOG.md).
3. Run `.\tests\smoke.ps1` and the manual checks. Push, and check that GitHub Actions passes.
4. Tag and release on GitHub, attaching a zip whose top-level `PaneTag` folder holds the
   module files and `LICENSE` (users extract it into their Modules folder):
   ```powershell
   $v = '0.4.0'
   git tag -a "v$v" -m "PaneTag $v"; git push origin "v$v"
   $stage = "$env:TEMP\panetag-release\PaneTag"; New-Item -ItemType Directory -Force $stage | Out-Null
   'PaneTag.psd1', 'PaneTag.psm1', 'panetag.exe', 'ptag.exe' | ForEach-Object { Copy-Item "PaneTag\$_" $stage }
   Copy-Item LICENSE $stage
   Compress-Archive -Path $stage -DestinationPath "PaneTag-$v.zip"
   gh release create "v$v" "PaneTag-$v.zip" --title "PaneTag $v" --notes-file <notes.md>
   ```
   In Windows PowerShell, pass commit messages and release notes through files (`git commit -F`,
   `--notes-file`): embedded double quotes in native arguments get mangled.
5. Publish to the PowerShell Gallery from your own terminal:
   ```powershell
   .\tools\publish.ps1
   ```
   It installs [PSResourceGet](https://learn.microsoft.com/powershell/gallery/powershellget/overview)
   for your user if needed, builds, runs the smoke tests, stages the module files and asks
   for your API key with hidden input (or reads `$env:PSGALLERY_API_KEY`). `-WhatIf` does
   everything but the upload. For a dry run without a key, publish to a local folder:
   `Register-PSResourceRepository -Name Local -Uri C:\temp\repo -Trusted`, then
   `.\tools\publish.ps1 -Repository Local`.

   It uses PSResourceGet's `Publish-PSResource`, not PowerShellGet's `Publish-Module`:
   PowerShellGet 2.2.5 packs with `dotnet pack` whenever `dotnet.exe` is on PATH, and fails
   with "dotnet.exe failed to pack" on machines that have the .NET runtime but no SDK.
6. Update your own copy: `Update-Module PaneTag` for a Gallery install, or `.\install.ps1`
   for a from-source install. Don't keep both: a from-source copy sits directly in
   `Modules\PaneTag`, a Gallery copy in `Modules\PaneTag\<version>`. Then run
   `Enable-PaneTagClaudeHooks` if you use the Claude Code hooks (they point to `ptag.exe` by path).

The Gallery package contains prebuilt, unsigned `panetag.exe` and `ptag.exe`. Some antivirus
tools are wary of unsigned executables; signing them is a possible future step.
